# 短信 MCP 部署与接口决策

## 2026-11-11：App 文件直传

- App 工具通道只传文件元信息及签名引用，文件原始字节直接上传到服务端授权的 ImageX/TOS 地址。
- 材料由 MCP 申请并确认 ImageX 会话；CSV 由 MCP 从短信服务授权的地址回读，核对大小/SHA-256 并复用名单/引流校验。
- 上传确认绑定当前调用凭据与有效期，无跨实例草稿、共享数据库或本地文件服务；原始 AK/SK 不进入页面，上传能力仅给当前表单。
- 上传失败可以手动重选并保留表单；未知的正式业务提交继续防重，不自动重试。
- 用户确认尚未开放且无需兼容后，移除原 Base64 上传工具；App 只使用直传。
- 构建和本地验证方式见模块 README；真实宿主网络许可、API 权限与部署独立验收。

## 2026-11-11：统一表单优先工具面

- 模型只见 17 个只读查询和开表工具；22 个内部工具仅对 App 可见。可见性不替代鉴权。
- 不保留旧工具兼容、双模式或按宿主品牌分流。没有 MCP Apps 的客户端只能查询，业务办理使用支持表单的客户端或控制台。
- 七类页面覆盖开通、资质、签名、引流、模板申请、普通发送和群发任务；历史群发复用任务管理页面。
- 开表不执行写入。所有提交由客户在页面核对后执行，未知写结果不自动重试。


## 2026-11-12：名单检查合并与后端范围

- 名单统计和可选引流检查共用一次回读，App-only 工具由 22 个收敛为 21 个；模型可见工具仍为 17 个。
- 用户要求撤回全部 SMS 后端改动。MCP 的文件直传、名单读取合并和群发结果摘要保留，均不依赖已撤回的后端修改。
- 当前签名表单仍通过 GetSignatureIdentificationList 查询资质候选；候选查询切换到 GetApplySignatureBind 是后续独立改动，不能将本轮提交描述为已解决该超时。

## 2026-11-12：签名表单切换资质候选接口

- 签名表单通过现有 `query_sms_resources` 调用 `GetApplySignatureBind`，使用原生候选数组；不分页、不按资质逐条补查，不新增宿主可见工具。
- 候选只消费资质 ID、用途、资质名称和营业证件名称。无候选时接受后端原生的 `null` 或空数组，不伪造审核状态、可用状态或分页信息。
- 用户明确后端已有校验：签名提交直接调用 `ApplySmsSignatureV2`，删除 MCP 提交前重复查询资质的逻辑及其专用确认参数。页面的填写校验、名称风险提示和用户确认保留。
- 通用 `list_qualifications` 仍使用原接口；SMS 后端和标准 Skill 不改。本条是本地源码变更，不代表 OpenTOP 已发布或 veFaaS 已部署。


## 2026-11-12：删除表单的重复查询

- 用户确认去掉普通发送、群发试发的提交前模板和 CSV 定义查询；页面保留本地填写校验和确认，提交直接调用原生发送接口。MCP 不再额外承诺提交前模板正文比对，相关只用于复核的请求字段一并删除。
- 群发核对复用页面已加载的模板正文和 CSV 列定义；名单仍按既有签名引用回读一次，检查大小、摘要、表头、号码和重复数，并供可选引流检查复用。页面数据只用于预览，创建任务仍以 SMS 后端对实际文件的校验为准。
- 引流录入保留写入响应检查，删除成功后的逐条资源 ID 查询。需要 ID 时显式查询，不以额外读操作决定写入是否受理。
- 资质转人工复核、协议核对、服务状态及发送回执查询、上传授权和完整性检查保持。SMS 后端和标准 Skill 均不改。

## 2026-11-13：创建签名页面对齐国内短信 Skill

- 用户确认所有接口以当前 MCP 为准，资质候选继续使用 `GetApplySignatureBind`。材料继续页面直传 ImageX，单文件保留 10 MB 限制，提交只调用 `ApplySmsSignatureV2`，不恢复提交前资质查询。审核状态使用 `ListSignaturesForAgent`，与 Skill 的查询指引一致。
- 页面沿用 Skill 的两步布局、Arco 控件、字段及枚举、名称校验、归属筛选、有效预填资质锁定和风险确认弹窗。原签名 CSS 保持一致，宿主只适配容器高度和深色主题。
- 所有材料分类共用五份上限；隐藏来源的材料不提交，预填草稿上传后转为私密引用，所有编辑撤销旧预览。放弃填写不新增服务端接口。未知写结果继续防重。

## 2026-11-13：引流录入页面对齐国内短信 Skill

- 页面沿用 Skill 的字段、枚举、Arco 控件、样式及预览布局。自有链接可选填跳转资料，火山短链只提交跳转分支；域名和 Path 在页面自动解析，保留完整原始链接。协议随文案链接识别，预填号码推断类型；手机和企业号码隔离各自的私密字段。
- 所有接口以 MCP 为准：预览调用 `preview_traffic_resource`，写入调用 `submit_traffic_resources` 及既有批量录入接口。保留 MCP 的批量上限、协议和重复项校验、空字符串受理判断，不恢复逐条 ID 回查，不新增服务端结束接口。
- 与 Skill 一致，客户预览后点击“确认录入”；所有编辑和行增删撤销旧确认，已知失败需重新预览，未知结果锁定编辑、结束和重试。结束只清理页面草稿并报告状态，模型不接收个人号码和证件资料。
- 预览按钮和普通输入框 Enter 不依赖原生表单提交，适配无 `allow-forms` 的宿主；主题覆盖仅维护在 `host.css`，业务 CSS 与参考文件一致。
